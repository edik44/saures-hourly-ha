# saures-hourly-ha

Почасовой расход воды со счётчиков **SAURES** в долгосрочной статистике **Home Assistant** — пакет YAML и карточка.

## Зачем

Контроллер SAURES выходит на связь раз в сутки. Интеграции, которые берут из облака текущее показание счётчика,
дают Home Assistant одну «ступеньку» в момент связи — и весь расход за сутки ложится в один час.

Этот пакет раз в сутки забирает из API личного кабинета SAURES почасовой журнал счётчика и кладёт расход в статистику
Home Assistant **по настоящим часам**:

- часовые, дневные и месячные столбцы показывают реальный расход;
- после перерыва связи (контроллер хранит почасовой журнал) пропущенные дни ложатся каждый на своё место;
- при первом запуске загружается вся история (по умолчанию за 2 года): по дням, а последние 35 дней — по часам;
- стоимость в рублях считается по тарифам с датами начала действия;
- уведомление, если контроллер не выходил на связь больше 2 суток, и когда связь вернулась.

## Что внутри

| Файл | Что это |
|---|---|
| `packages/saures.yaml` | пакет: синхронизация, сенсоры, помощники, автоматизации |
| `dashboards/saures_water_card.yaml` | карточка «Вода»: показание, вчера, за месяц, графики по часам, дням и месяцам в м³ или ₽ |

## Требования

- Home Assistant 2026.x (проверено на 2026.10).
- Учётная запись личного кабинета SAURES с контроллером и счётчиком воды.
- [HACS](https://hacs.xyz) и интеграция **Import Statistics**
  ([klausj1/homeassistant-statistics](https://github.com/klausj1/homeassistant-statistics)) версии 5.3 или новее —
  через неё пакет пишет почасовые данные в статистику.
- Для карточки (HACS, раздел «Интерфейс»): **Mushroom** 5+, **ApexCharts card**, **vertical-stack-in-card**, **card_mod**.

## Установка

1. Добавьте логин и пароль личного кабинета SAURES в `/config/secrets.yaml`:
   ```yaml
   saures_email: "ваш@email"
   saures_password: "пароль"
   ```
2. Если пакеты ещё не подключены, добавьте в `configuration.yaml`:
   ```yaml
   homeassistant:
     packages: !include_dir_named packages
   ```
3. Скопируйте `packages/saures.yaml` в `/config/packages/saures.yaml`.
4. Настройки — в блоке `НАСТРОЙКИ` в начале скрипта `saures_sinhronizatsiia`. По умолчанию ничего менять не нужно:
   объект, счётчик холодной воды и часовой пояс определяются сами (см. «Настройки» ниже).
5. Инструменты разработчика → YAML → «Проверить конфигурацию» → «Перезапустить».
6. Сразу после запуска введите тариф в помощнике **«Тариф воды»** (₽ за м³).
7. Через 2 минуты после запуска автоматизация загрузит всю историю (около минуты). Проверка
   (Инструменты разработчика → Шаблон):
   ```
   {{ states('sensor.voda_saures_status') }}
   ```
   Ожидается `ok: вся история — … дн. по дням и … ч по часам, всего … м³ = … ₽`. Если тариф ввели позже загрузки,
   запустите «SAURES синхронизация воды» с полем «Вся история заново» — рубли пересчитаются.
8. Карточка: панель → «Изменить» → «Добавить карточку» → «Вручную» → вставьте `dashboards/saures_water_card.yaml`.

Ручной запуск в любое время (не чаще раза в 5 минут): Инструменты разработчика → Действия →
«SAURES синхронизация воды», или кнопка «Обновить» в карточке.

## Настройки

Блок `НАСТРОЙКИ` в скрипте `saures_sinhronizatsiia`:

| Параметр | По умолчанию | Что это |
|---|---|---|
| `obekt_id` | `0` | объект кабинета SAURES; `0` — первый |
| `schetchik_id` | `0` | `meter_id` счётчика; `0` — первый счётчик холодной воды объекта (нет — первый счётчик воды) |
| `istoriia_s` | `""` | с какого дня грузить историю (`"ГГГГ-ММ-ДД"`); пусто — за последние 2 года |
| `tarify_tablica` | `[]` | прошлые тарифы: `[["ГГГГ-ММ-ДД", цена], …]`, дата — начало действия |

`id` объектов и счётчиков, их часовой пояс и последние показания показывает скрипт **«SAURES проверка API»**
(Инструменты разработчика → Действия → запустить → ответ внизу). Серийного номера, адреса и пароля в отчёте нет.

## Как это работает

- **Расписание** (автоматизация «Вода SAURES — синхронизация»): проверка в 23:45; запасные — в 05:45, 11:45, 17:45 и
  при запуске HA, но только если данных нет больше 20 часов. В 00:05 — пересчёт «вчера» и «за месяц» без запросов к
  SAURES. Контроллер выходит на связь раз в сутки; время связи сдвигается на момент нажатия кнопки на контроллере.
- **Синхронизация**: вход → объект и его часовой пояс → контроллер и счётчик. Если контроллер выходил на связь после
  прошлой загрузки — загружаются часы с полуночи за 2 дня до прошлой загрузки до сейчас (перезаписываются, поэтому
  неполный последний час выправляется сам). Если новых данных нет — обновляются только батарея, сигнал и время связи.
- **Статистика** пишется в два «сенсора-носителя» — `sensor.voda_saures_raskhod` (м³) и `sensor.voda_saures_stoimost`
  (₽). Их состояние — до какого времени загружены данные, а не число: так Home Assistant не пишет в их статистику свои
  записи. Единицы у их статистики нет (Import Statistics принимает только единицу самого сенсора), м³ и ₽ подписывает
  карточка. Если в «Инструменты разработчика → Статистика» у них появится «Исправить» — **не нажимайте**: это удалит
  историю.
- **Время**: API отдаёт время по часам объекта SAURES; пакет переводит его сам, столбцы — по календарю Home Assistant.
- **Правила API SAURES**: один вход на запуск, пауза 3 с между запросами, запуск не чаще раза в 5 минут — иначе сервер
  на минуту блокирует адрес.

## Сущности

| Сущность | Что это |
|---|---|
| `sensor.voda_saures_pokazanie` | показание счётчика, м³ |
| `sensor.voda_saures_vchera`, `sensor.voda_saures_vchera_rub` | расход за вчера, м³ и ₽ |
| `sensor.voda_saures_za_mesiats`, `sensor.voda_saures_za_mesiats_rub` | с начала месяца, м³ и ₽ |
| `sensor.voda_saures_batareia`, `sensor.voda_saures_signal` | батарея (%) и сигнал Wi-Fi (dBm) контроллера |
| `sensor.voda_saures_sviaz` | время последней связи контроллера |
| `sensor.voda_saures_raskhod`, `sensor.voda_saures_stoimost` | носители статистики (м³, ₽) |
| `sensor.voda_saures_status` | итог последнего запуска |
| `input_number.tarif_vody`, `input_datetime.tarif_vody_s` | текущий тариф и дата начала его действия |
| `input_boolean.pokazyvat_raskhod_vody_v_rubliakh`, `input_select.vid_grafika_vody` | переключатели карточки |

Скрипты: «SAURES синхронизация воды», «SAURES загрузка всей истории воды», «SAURES итоги воды»,
«SAURES уведомление», «SAURES проверка API», «График воды».

Идентификаторы скриптов берутся из ключей пакета: `script.saures_sinhronizatsiia` (на него ссылается кнопка
«Обновить» в карточке), `script.saures_istoriia`, `script.saures_itogi`, `script.saures_uvedomlenie`,
`script.saures_proverka`, `script.grafik_vody`. Идентификаторы автоматизаций Home Assistant берёт из названия и
переводит кириллицу по своим правилам («х» → «kh»): `automation.voda_saures_sinkhronizatsiia` и
`automation.voda_saures_net_sviazi_2_sutok`. Разное написание у скрипта и автоматизации («sinhr…» и «sinkhr…») — не
ошибка: ни пакет, ни карточка на идентификаторы автоматизаций не ссылаются.

## Тарифы

Текущий тариф — в помощниках «Тариф воды» (₽ за м³) и «Тариф воды действует с» (дата; пусто — цена действует для всей
истории). Прошлые — в `tarify_tablica`. Цена часа — тариф с самой поздней датой начала, не позже этого часа; часы раньше
самого раннего тарифа считаются по самому раннему.

Смена тарифа, например с 01.07.2027 — 80 ₽:
1. «Тариф воды» → 80, «Тариф воды действует с» → 01.07.2027.
2. Если дата уже прошла больше чем на 2 дня — запустите синхронизацию с полем «Загрузить заново, дней» от этой даты.
3. Прежнюю цену допишите в `tarify_tablica` (нужно для полной перезагрузки истории).

## Уведомления

Скрипт **«SAURES уведомление»** вызывается, когда контроллер не выходил на связь больше 2 суток и когда связь
вернулась. По умолчанию он создаёт уведомление в интерфейсе Home Assistant. Свои каналы (телефон, почту) добавьте в
блок `УВЕДОМЛЕНИЯ` этого скрипта — пример там в комментарии.

## Если что-то не так

Сначала смотрите `sensor.voda_saures_status` и трассировку скрипта «SAURES синхронизация воды»
(Настройки → Автоматизации и сцены → Скрипты → ⋮ → «Трассировки»).

| Что видно | Что делать |
|---|---|
| `ошибка входа: HTTP 403` | сервер SAURES не пускает запросы Home Assistant. В 2026 году такой фильтр уже снимали по обращению в поддержку SAURES — напишите им, что используете Home Assistant и 1–5 запросов в сутки. Подменять подпись клиента пакет не будет |
| `ошибка входа: … WrongCreds…` | неверный логин или пароль в `secrets.yaml` |
| `IPBlockException` | слишком частые запросы; подождите минуту и не запускайте чаще раза в 5 минут |
| `объект … не найден`, `нет данных счётчика …` | укажите `obekt_id` / `schetchik_id` по отчёту «SAURES проверка API» |
| `часовой пояс объекта … не поддерживается` | поддерживаются только целые часы (например `+03:00`) |
| статус висит на `загрузка …` | не установлена или не запустилась Import Statistics; смотрите журнал и трассировку |
| `Unit mismatch …` | обновите пакет: загрузка должна идти с пустой единицей (`unit: ""`) |
| скрипт «не активен», `Only one type can be specified` | не используйте `{}` в пакетах: при слиянии пакета Home Assistant выбрасывает пустые словари |
| кнопка «Обновить» в карточке ничего не запускает и не синеет | у скрипта синхронизации другой идентификатор, например `script.saures_sinkhronizatsiia_vody`: если скрипт хоть раз не прошёл проверку, Home Assistant берёт идентификатор из названия и сохраняет его. Переименуйте: Настройки → Устройства и службы → Объекты → «SAURES синхронизация воды» → ⚙ → «ID объекта» → `script.saures_sinhronizatsiia` (или впишите в карточку тот, что получился) |

## Ограничения

- Один счётчик (по умолчанию — холодная вода). Несколько счётчиков на одной учётной записи (например, вода и газ) —
  в следующей версии. Простая копия пакета для второго счётчика не подойдёт: общие `rest_command` и помощники,
  одинаковые события и имена, два входа в API подряд.
- Часовой пояс объекта — только целые часы.
- Данные появляются после связи контроллера, то есть раз в сутки; «вчера» после полуночи может быть без последних часов
  суток — они дозагрузятся вечером.
- На одной учётной записи SAURES — одна такая синхронизация (общий лимит запросов).

## Поддержка

Пакет выложен как есть. Ошибки и вопросы — в Issues; отвечаю по возможности, без сроков и гарантий. Перед вопросом
посмотрите раздел «Если что-то не так» и приложите текст `sensor.voda_saures_status`. Трассировку целиком не
выкладывайте: в шаге входа (`rest_command.saures_login`) видны логин и пароль SAURES. Если нужна трассировка — только
шаг с ошибкой.
